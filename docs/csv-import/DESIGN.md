# CSV読み込み機能 設計書

**ステータス: 検討中（議論の記録）**

## 1. 概要

### 背景

CSVファイルをSource of Truth（SoT）として運用するために、CSV出力だけでなくCSV読み込みも必要。
これにより以下の運用が可能になる:

- DBコンテナをバックアップ不要の作業用として割り切れる
- CSVからデータを復元できる（DB初期化・リカバリ）
- CSVを起点に新しい棚卸しセッションを開始できる

### ゴール

- 出力したCSVファイルを読み込んで、新しいセッションとしてDBに取り込む
- 1CSV = 1セッション

### 完成後の運用フロー

```
CSV (SoT)
  ↓ 読み込み
新セッション作成（商品・SKU・カウントをセット）
  ↓
既存セッション再開・編集（※別途実装が必要）
  ↓
CSV出力 → SoT として保存
  ↓
繰り返し
```

---

## 2. ユースケース

| ユースケース | 数量の扱い | 想定シーン |
|---|---|---|
| DB初期化（リカバリ） | CSVの数量をそのまま使う | DBが壊れた・コンテナを作り直した |
| 新セッション開始 | 数量を0にリセット | 前回のCSVを元に商品・SKUだけ復元して新規棚卸し |

読み込み時に **オプションで選択** できるようにする:
- 「CSVの数量を引き継ぐ」
- 「数量を0にリセットする」

## 3. CSVパース仕様

### 入力フォーマット（現在の出力形式に準拠）

```csv
商品名,価格,数量,小計
靴,1600,3,4800
靴,2700,5,13500
財布,2700,2,5400
,,合計,23700

商品別集計
商品名,数量,小計
靴,8,18300
財布,2,5400
,合計,23700
```

### パースルール

| 行の種類 | 判定方法 | 処理 |
|---|---|---|
| ヘッダー行 | 1行目（`商品名,価格,数量,小計`） | スキップ |
| データ行 | 商品名と価格が存在する行 | 読み込み対象 |
| 合計行 | 3列目が「合計」 | スキップ |
| 空行 | 全列が空 | スキップ |
| 商品別集計セクション | 「商品別集計」以降の全行 | スキップ |

### 読み取る列

| 列 | 用途 | 備考 |
|---|---|---|
| 商品名 | 商品の特定・作成 | |
| 価格 | SKUの特定・作成 | |
| 数量 | カウントのセット | オプションにより0リセットも可 |
| 小計 | 使用しない | 計算で導出可能なので読み飛ばし |

---

## 4. 処理フロー

```
1. CSVファイルを受け取る
2. パース（商品別集計セクション以降は無視）
3. 行ごとに処理:
   a. 商品名で products を検索
      → 存在しなければ CREATE
      → 存在すれば既存を使用
   b. 商品ID + 価格で skus を検索
      → 存在しなければ CREATE
      → 存在すれば既存を使用
   c. 読み取った数量を記録（後でまとめてINSERT）
4. 新しいセッションを作成（status: in_progress）
5. count_items にデータを投入
   → オプション「数量を引き継ぐ」: CSVの数量をセット
   → オプション「0リセット」: 数量0でセット（またはcount_itemsを作らない）
```

### 既存データとの関係

- 商品・SKU: **既存があればそのまま使う（重複作成しない）**
- セッション: **常に新規作成**（既存セッションには影響しない）
- count_items: 新セッションに紐づくので既存データと競合しない

## 5. 前提・依存する機能

### 既存セッションの再開・編集（未実装）

CSV読み込みで作成したセッションを編集するためには、既存セッションを再開する機能が必要。
現在は棚卸し画面を開くと進行中セッションが表示されるため、
CSV読み込みでセッションを `in_progress` で作成すれば、そのまま棚卸し画面で編集できる。

ただし完了したセッションを再度編集したい場合は、セッション再開機能が別途必要。

### `in_progress` セッションの制約

同時に `in_progress` のセッションは1つのみ。
CSV読み込み時に既に `in_progress` セッションがある場合の扱い:
- エラーにする
- または既存を自動的に `completed` にする

→ **要検討**
